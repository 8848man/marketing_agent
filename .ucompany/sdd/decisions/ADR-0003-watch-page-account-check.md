# ADR-0003 — 계정 확인·로그인은 허용 영상 watch 페이지에서만

## 맥락

PDF 4쪽 안전 규칙: "우리 채널 영상(과 본인 테스트 영상) 페이지 말고는 열지 않고, 댓글 작성 외의 동작은 하지 않습니다." 기존 구현은 계정 확인에 `https://www.youtube.com/` 홈을, 로그인 창에 `accounts.google.com/AccountChooser?continue=myaccount.google.com`을 프로그램이 직접 열었고, 이메일을 읽으려고 계정 메뉴를 클릭했다. README가 스스로 "미충족"이라 적었고 심사자 코드 검사에서 실격 사유가 될 수 있었다.

## 결정 (사용자 승인 2026-10-18, 결정표 A안)

1. 확인용 페이지는 허용 채널 영상의 watch 페이지다. 불러온 영상이 있으면 그중 하나, 없으면 PDF 2쪽 예시 영상(우리 채널 소속) 중 현재 설정 채널에 속한 것.
2. 판정은 화면에 보이는 것만 쓴다: 아바타 버튼 = 로그인됨, "로그인" 링크 = 로그아웃, 그 외 = 확인 불가. 계정 메뉴 클릭·이메일 읽기는 하지 않는다.
3. 로그인 창은 같은 watch 페이지를 앱 전용 프로필(비자동화 Chrome 프로세스)로 연다. Google 로그인 화면으로의 이동은 사용자가 YouTube의 "로그인" 버튼을 눌러서만 일어난다.
4. 어떤 계정으로 게시됐는지는 게시 후 작성자 링크 확인(기존)으로 증명한다.

## 결과

- 프로필 목록에 이메일이 표시되지 않는다("로그인됨"만 표시).
- `safety_scan.py --strict`가 WARN 0으로 통과해야 한다.
- 앱 전용 프로필 방식(심사자 1회 로그인)은 유지한다. 심사 PC 프로필의 실제 형태는 출제처 확인 불가(휴일)이며, 이 방식은 두 해석 모두에서 동작한다.
