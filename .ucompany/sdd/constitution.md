- 제품은 `marketing_agent/` 한 곳에서 실행하는 로컬 웹 대시보드다. 기본 흐름은 영상 불러오기 → 영상 선택과 승인 초안 확인 → 사용자의 명시적 댓글 게시 클릭이다. 오프라인 데모의 성공은 실제 YouTube 게시 증거가 아니다.

## 게시 안전 경계

- 영상·채널 소속을 확인할 수 없거나 RSS 응답이 실패하면 게시하지 않는다. 초안의 영상·채널·제목·승인 해시가 현재 선택과 다르거나 사람 승인이 없으면 게시하지 않는다.
- 게시 진입점은 사용자가 누르는 버튼 하나다. 게시 요청에서 Host·Origin·세션 토큰을 확인하고, 거부된 요청은 DB 예약과 Chrome 실행이 모두 0회여야 한다.
- 한 영상에 실제 댓글 하나, Mac 로컬 날짜 기준 앱 전체 하루 최대 10개를 지킨다. 영상의 담당 프로필은 등록된 앱 전용 프로필 사이에서 영속 순환 배정하며, AI 초안·게시에 같은 담당을 사용한다. 게시 결과가 불명확하면 자동 재시도하지 않고 수동 확인까지 예약을 유지한다.
- 개발 중 실게시 검증은 소유가 확인된 본인 테스트 영상에 한정한다. 우리 채널 영상의 사전 게시는 하지 않는다. 공개·외부 제출은 별도의 사용자 승인 후 진행한다.

## 파일·비밀정보·검증

- 실제 설정과 비밀정보는 Git 제외된 로컬 파일에서 관리한다. 웹 설정 화면은 저장된 키·쿠키·프로필 내부 파일을 표시하지 않는다. 사용자가 AI API 관리에서 직접 입력한 키는 localhost의 쓰기 전용 입력으로 받아 로컬 설정에만 저장하고 응답·로그·초안에 반환하지 않는다.
- Chrome 프로필은 지정된 Mac 환경에서 보이는 브라우저로 열되, 앱 코드가 프로필의 쿠키·비밀번호 파일을 직접 읽거나 복사하지 않는다. 프로필 경로·로그인·잠금 실패는 게시 차단 사유다.
- Windows 회귀 시험, 오프라인 데모, 실제 5채널 RSS 응답, Mac 프로필/한국어 화면, 실제 댓글 게시를 서로 다른 증거로 기록한다. 검증하지 못한 관문은 통과로 표시하지 않는다.
- 문서 상태를 바꿀 때 `AGENTS.md`의 단계 확인 규칙을 따르고 `tasks.md`·`00_index.md`·`graph.json`·`handoff.md`를 함께 갱신한다.
