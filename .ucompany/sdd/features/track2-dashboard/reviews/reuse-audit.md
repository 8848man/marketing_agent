# 기존 `marketing_agent/` 재사용 평가

> 최초 대시보드 설계 당시의 재사용 판단을 보존한 **이력 문서**다. 현재 코드에서 기능 제거·수정이 완료됐다는 증거로 쓰지 않는다. 현행 문서 권위는 [`.ucompany/sdd/source-of-truth.md`](../../../source-of-truth.md)를 따른다.

> 대상: `D:/projects/샘플_폴더/샘플프로젝트/marketing_agent`의 현재 코드. 판단 기준은 `spec.md`의 PDF 필수 요구사항이다. 이 표는 **구현 계획**이며 기존 앱의 PDF 충족 판정이 아니다. 기존 패키지를 확장하고, 같은 기능의 두 번째 제품은 만들지 않는다.

## 재사용을 연결하는 구현 순서

1. 기존 패키지에 로컬 서버·UI를 추가하고, 설정 진입점에서 AI 키나 YouTube Data API 키 없이 화면을 띄운다(T01).
2. PDF의 다섯 채널을 설정에 고정하고 RSS 응답을 `video_id`·`channel_id`·제목·발행 시각·썸네일로 정규화한다(T02). RSS에서 얻은 출처를 보존하되 화면 입력만으로 소속을 확정하지 않는다.
3. `drafts/` 초안 형식과 기존 작성 검증을 연결한다(T03~T05). 선택은 읽기만 하고, 검토된 실제 최신 초안만 게시 가능하게 한다.
4. 게시 클릭 시 YouTube RSS를 재조회해 영상·채널 ID를 확인한다(T06). RSS 밖 영상의 공개 메타데이터 확인은 G1 실측을 통과한 뒤에만 사용한다. 검증 불가면 중단한다. 확인 과정은 허용되지 않은 Chrome 영상 페이지를 먼저 여는 방식이어서는 안 된다.
5. SQLite 원자 예약 뒤 지정 프로필의 보이는 Chrome에서 글자별 입력·게시·확인을 수행한다(T07~T09). 결과 불명확은 보류하고 수동 확인을 요구한다.
6. 기존 CLI 기능은 가점 또는 개발 보조 경로로 격리한다. 자동 검색/분류가 기본 대시보드의 선택이나 게시를 선점하지 못하게 한다.

## 검증 범위

- 현재 앱의 기존 테스트는 로컬에서 `70 passed`였다. 이는 현행 CLI·모의 브라우저 로직의 회귀 기준일 뿐, Mac 대시보드·프로필 사용·글자별 입력·실제 게시를 증명하지 않는다.
- 새로운 수락 시험은 `tasks.md`의 T01~T12와 `checklist.md`의 PDF 항목을 따른다. Mac 실환경 게시 시험은 본인 테스트 영상에서만 수행한다.
- 모듈별 결정은 현재 소스 기준이다. 실제 구현 시 함수 시그니처와 데이터 마이그레이션을 다시 확인하고 이 문서의 상태를 갱신한다.
