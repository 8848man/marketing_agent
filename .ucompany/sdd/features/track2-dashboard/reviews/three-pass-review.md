# 계획 개선과 자기 비판 — 3회

> 원본 `track-2-marketing-agent (1).pdf`를 요구사항의 기준으로 사용한다. 각 회차는 문서 수정 → 자체 비판 → 다음 수정의 순서로 진행했다. 기술 실험 결과를 꾸며 쓰지 않는다.

## 1회차 — 채널 확인과 초안 최신성

**수정:** `plan.md`에 키 없는 RSS 재조회, RSS 밖 영상의 별도 확인 관문, 초안 ID·채널·제목·버전 일치 조건을 추가했다. `tasks.md`에 G1과 관련 수락 조건을 추가했다.

**자기 비판:** RSS가 실패하거나 영상이 최신 피드에서 빠졌을 때 안전하게 차단할 수는 있지만, 그러면 PDF가 허용한 우리 채널의 모든 영상 중 일부가 게시 불가해진다. 공개 메타데이터 방식은 아직 실측되지 않았다. 또한 초안 버전을 어떻게 계산하고, 선택 후 바뀐 초안을 어떻게 사용자에게 보여줄지가 불명확하다. 게시 시도/실패/성공을 어떤 상태로 기록할지도 정리되지 않아 기존 DB 로직을 그대로 가져오면 중복 방지와 재시도가 충돌한다.

## 2회차 — 프로필 실행과 게시 상태

**수정:** `plan.md`에 사용자 데이터 디렉터리와 프로필 하위 이름의 구분, 잠금/미로그인 때 중단, 초안 SHA-256 버전, 영상 공통 예약과 게시 전 실패·게시 후 결과 불명확의 상태 전이를 추가했다. `tasks.md`의 G2/T06/T07과 `reuse-audit.md`의 저장소 재사용 판단을 수정했다.

**자기 비판:** 프로필 실행 절차는 아직 Mac 실측 없이 설계한 것이므로 `launchPersistentContext`가 심사자에게 설치된 기존 프로필을 그대로 다룰 수 있다고 단정할 수 없다. 현재 문서에는 실험 환경·결과를 기록할 장소가 없고, 위험한 프로필 조작을 피하면서 실패를 사용자에게 설명하는 UI 수락 기준도 약하다. 또한 70개 기존 테스트와 새 PDF 요구사항의 추적 표가 없어 최종 체크리스트가 다시 선언적 문서가 될 수 있다. 이 한계를 3회차에 검증 기록 양식과 요구사항별 증거 조건으로 보완한다.

## 3회차 — 완료 판정의 증거 기준

**수정:** `validation-protocol.md`를 만들어 G1-A/B/C, G2, ①~③, 운영·안전·제출의 시험 방법과 합격 증거를 정했다. `checklist.md`의 기존 코드 편입 문구를 댓글 1개 상태 정책에 맞게 고치고, 미실측 관문을 별도 표에 표시했다. `plan.md`의 프로필 구현 단정을 낮추고, 게시 버튼 클릭 전/후 실패를 구분했다. 검토 뒤 본문 수정이 승인으로 오인되지 않도록 콘텐츠/승인 해시를 분리하고, 예약 후 자정을 넘길 때 게시 직전 새 날짜의 상한을 다시 확인하도록 했다.

**자기 비판:** 세 회차를 거쳐도 Mac에서 실제 Chrome 프로필을 열거나 라이브 RSS·공개 메타데이터의 구조를 확인한 결과는 없다. 따라서 G1-A/B와 G2는 필수 기능의 기술 위험으로 남아 있으며, `validation-protocol.md`는 증거를 채울 틀일 뿐 증거 자체가 아니다. RSS 밖 영상의 채널 확인이 불안정하면 직접 URL 가점은 보류해야 한다. 또한 PDF의 “대시보드 폴더 밖 파일을 읽지 않는다”와 Chrome의 기존 프로필 사용이 어떻게 양립하는지는 코드 수준의 경계와 Mac 실행 추적으로 입증해야 한다. 이 항목들을 미완료로 유지했다.
