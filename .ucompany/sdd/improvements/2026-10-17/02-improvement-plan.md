## 2. `.example` 파일과 실제 계약 정리

실제 `.env`와 `config.yaml` 값은 열지 않는다. 일관성은 예시 파일, 파서, 저장기, README, 민감도 정책의 **스키마**로 비교한다.

| 파일 | 정리할 내용 | 확인 방법 |
| --- | --- | --- |
| `.env.example` | `YOUTUBE_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `XAI_API_KEY`의 선택 여부·사용처·우선순위·키 보관 위치를 명시한다. 빈 값은 비밀이 아님을 유지한다. | `DashboardSettings._read_ai_env`, `youtube_api_key`, `ai_credentials`, 저장 함수와 변수 이름 및 인용/공백 규칙을 대조한다. 키 값은 출력하지 않는다. |
| `config.example.yaml` | 대시보드용 필드와 레거시 CLI 전용 필드를 구획하거나 별도 예시로 분리한다. `chrome_debug_url`·`allowed_videos`·`trigger`가 기본 대시보드 경로에서 쓰이지 않음을 명시한다. 프로필은 Chrome 내부 경로가 아닌 앱 표시 이름임을 적는다. | `load_config`와 `DashboardSettings._validate` 양쪽에서 예시를 구조 검사하고, 각 필드의 소비 위치를 표로 남긴다. |
| README/SDD | 설치 의존성과 `playwright` 설치 절차, 앱 전용 프로필, 키 선택 사용, 데이터 경로, 테스트 영상 등록을 예시와 동일하게 설명한다. | 빈 예시를 복사한 가상 환경의 정적 설정 검사를 먼저 수행하고, 실행 검증은 별도 단계로 둔다. |

**완료 기준:** 예시의 모든 변수/필드가 코드에서 소비되거나 `레거시/미사용`으로 표시된다. 예시만 보고 기본 대시보드의 필수·선택 설정을 구분할 수 있다. 비밀값이 예시에 들어가지 않는다.

## 3. 순서가 있는 프로그램 개선 작업

| 순서 | 작업 | 구체 산출물 | 통과 조건 |
| --- | --- | --- | --- |
| P0-1 | 로컬 서버 접근 정책 결정 | SEC-01 위협 모델 및 API별 정보 분류표. 민감 GET 인증, 캡처 접근, 루프백 토큰의 한계를 명시한 설계 | 다른 로컬 프로세스·브라우저 출처별 허용/거부 시나리오가 정해지고, 초안·캡처 무단 조회 시험이 통과한다. |
| P0-2 | 게시 진입점 단일화 | 레거시 CLI의 게시 가능 여부에 대한 결정 기록. 남긴다면 대시보드와 동일 승인·예약 정책을 통과시키고, 없앤다면 CLI는 탐지/초안/오프라인 용도로 제한 | 인자 없는 CLI 및 모든 보조 진입점에서 사람 승인 없이 게시 함수가 호출되지 않는다. 거부 시 Chrome·DB 예약 0회를 확인한다. |
| P0-3 | 외부 호출 비밀 경계 통합 | YouTube/AI 요청의 공식 호스트·리다이렉트·오류 코드·키 전달 방식 표와 공통 HTTP 정책 | 리다이렉트 및 오류 응답에서 키가 다른 호스트, 화면, 로그에 나타나지 않는 회귀 시험이 통과한다. |
| P1-1 | `dashboard.py` 분해 | HTTP 라우터/입력 스키마, 앱 서비스, 설정·비밀 저장, UI 자산의 명시적 경계와 `DashboardService` 확장 계약 | HTTP 거부·승인·게시 상태 회귀가 유지되고 `hasattr` 기반 핵심 분기가 제거된다. |
| P1-2 | 외부 근거·프롬프트 경계 | 근거별 길이 제한·출처 표시·프롬프트 버전, 초안 검토 화면의 근거 추적 | 악성 지시문/긴 자막/오염된 인기 댓글 사례에서 승인 전 근거와 결과가 분리돼 보이고 규칙 위반 초안이 게시되지 않는다. |
| P1-3 | 제공사 교체 계약 | `DraftGenerator`/`PromptPolicy` 인터페이스, 제공사 등록 메타데이터, 스키마/오류/보존 옵션 지원 표 | 기본 네 제공사를 동일 계약 시험으로 확인하고, 새 모의 제공사를 핵심 대시보드 수정 없이 등록할 수 있다. 실 API 동등성은 제공사별로 따로 확인한다. |
| P1-4 | 파일 경계 통일 | 초안·설정·키·캡처의 허용 경로, 파일 유형·크기·권한·원자 교체 정책 | 심볼릭 링크·너무 큰 파일·경로 탈출·동시 교체 시험에서 정의된 차단/복구 동작을 보인다. |
| P2-1 | 불필요 코드 결정 | 레거시 `pipeline/watcher/search_budget/trigger/classifier/writer/ChromeBrowser` 사용처 표. 실제 지원 기능과 가점을 구분 | 사용하지 않는 경로는 제거하거나 격리하고, 남기는 경로에는 명시적 진입점·책임자·시험이 있다. 데이터 마이그레이션 없이 DB 테이블을 삭제하지 않는다. |
| P2-2 | 문서 정리 적용 | SDD 권위·결정 기록, 현재 상태 표, `.example` 설명, 오래된 문서의 `대체됨` 표시 | 원문 링크·현재 판정·예시 계약의 자동 점검과 사람 검토를 통과한다. |

P0 작업은 보안 경계와 게시 정책부터 확정한다. 실제 코드 수정 때는 프로젝트 [`AGENTS.md`](../../../../AGENTS.md)에 따라 `spec.md` → `plan.md` → `tasks.md` → 코드 순서로 반영하고, 테스트 증거와 색인·그래프·인계를 갱신한다. 이 계획 문서 자체는 기능 구현 승인이나 수락 완료 표시가 아니다.

## 4. 검증과 배포 판단

1. **정적 확인:** SDD 링크/ID/대체 관계, 예시 스키마, 외부 도메인·파일 경로·게시 호출 전수 검색.
2. **격리 회귀:** 인증 없는 GET, Origin·Host·토큰, CLI 기본 실행, 리다이렉트/키 오류, 악성 근거, 초안 심볼릭 링크, 제공사 교체, 중복 게시·자정 경계를 모의 입력으로 확인한다.
3. **실환경 수락:** Windows와 macOS를 분리해 앱 전용 Chrome, 한국어 YouTube 화면, 실제 RSS·AI 제공사, 본인 테스트 영상 게시를 검증한다. 외부 호출·실제 게시에는 기존 사용자 승인 절차를 적용한다.
4. **판정:** 자동 시험 통과와 외부 제공사/브라우저 실환경 수락을 구분한다. 안전 규칙의 Google 로그인 도메인·브라우저 저장·외부 프로필 해석은 결정 기록과 검증 전까지 미해결로 표시한다.

이번 요청에서는 계획 수립까지만 수행한다. 위 단계의 코드 수정, 기존 문서 재작성, 설정 이동, 테스트 실행, 외부 호출은 후속 작업이다.
