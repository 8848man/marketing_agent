# 3. 알려진 한계와 복구 방법

| 한계 | 영향 | 대응·복구 |
| --- | --- | --- |
| 같은 OS 사용자로 실행되는 다른 프로그램은 여전히 대시보드를 조작할 수 있음 | ADR-0002가 수용한 위험. 그런 프로그램은 앱 폴더·Chrome 프로필도 직접 읽을 수 있음 | 신뢰하지 않는 프로그램을 같은 계정에서 실행하지 않기 |
| Windows 키 저장소를 다른 PC·다른 Windows 사용자에서 복사해 오면 복호화 불가 | 키 저장이 `SECRET_STORE_UNAVAILABLE`로 계속 실패 | `data/dashboard/secrets.dpapi.json`을 지우고 설정에서 키를 다시 입력 |
| 키 저장소 파일이 깨진 경우 | 자동으로 `secrets.dpapi.json.bad-<시각>`로 옮기고 새로 저장 | 키를 다시 입력 |
| macOS·Linux는 키를 `.env`(권한 0600)에 평문 보관 | POSIX 권한으로 다른 사용자는 못 읽음 | 필요하면 운영 시 키체인 연동 검토 |
| 대시보드를 같은 폴더에서 두 개 동시에 띄우는 경우 | 키 저장소·로그 파일에 프로세스 간 잠금이 없음 | 한 번에 하나만 실행 |
| 스타일 CSP는 `'unsafe-inline'` 유지 | 인라인 style 속성이 많아 이번 범위에서 제외 | 다음 개선 후보 |
| DB 스키마 버전 | 이번 빌드부터 더 새 버전 DB를 거부(`DB_SCHEMA_NEWER`). 이번 개선 이전 코드로 되돌리면 그 검사가 없음 | 버전 2를 만들 때 롤백 지침 문서화 필요. 되돌릴 때는 B항 백업 DB 사용 |
| 브라우저 화면·실제 게시는 자동 검증 못 함 | Linux 작업 환경, 헤드리스 Chromium 설치 실패 | 1번 체크리스트 C·D |
| Windows 전용 DPAPI 코드는 가짜 암호화 함수로만 시험 | 시그니처는 코드 검토로 확인 | 1번 체크리스트 C |
| 결과 불명 게시를 "종료"하면 그 영상에는 다시 게시하지 않음 | 의도된 설계(중복 게시 방지) | 정말 안 달린 경우에도 재게시는 수동으로 판단 |
| 같은 채널 60분 간격 | 하루 10개 한도와 별개로 같은 채널 연속 게시가 막힘 | 다른 채널 영상을 고르거나 시간을 두고 게시 |
