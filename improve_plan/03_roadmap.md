# 03. 로드맵

## 5라운드 개요

| 라운드 | 주제 | 주요 항목 | 계획 | 구현 | 검토 | 예상 시간 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 즉시 조치 | N1, H2, M6, H4, 게이트 도구 | 메인 | Sonnet | Sonnet | 1~2시간 |
| 2 | 보안·승인 무결성 | H1, H3, M1 | 메인 | Sonnet | Sonnet + **메인 diff 정독** | 3~5시간 |
| 3 | 운영 안정성 | M2, M3, L4, L1, L2 | 메인 | Sonnet | Sonnet + **메인 diff 정독** | 2~4시간 |
| 4 | 구조 개선 A | M5, M4, L5 | 메인 | Sonnet | Sonnet | 3~5시간 |
| 5 | 구조 개선 B | M7, M8, L6, L3, L8 | 메인 | Sonnet | Sonnet | 3~5시간 |

라운드별 상세 계획은 [05_rounds/](05_rounds/index.md)에 있습니다.

## 순서의 근거

- 위험이 큰 순서(유출 → 승인 무결성 → 운영 → 구조)로 진행합니다.
- 1라운드에서 만드는 게이트 도구(`scripts/round_gate.py`)가 이후 모든 라운드의 검증 기반이 됩니다.
- 4라운드의 공통 HTTP 계층은 3라운드의 로깅 이후에 해야 오류 코드 체계를 한 번에 맞출 수 있습니다.
- 5라운드의 `dashboard.py` 분리는 2·3라운드의 보안·락 변경이 끝난 뒤에 해야 충돌이 적습니다.

## 브랜치 전략

1. 라운드 시작 시 최신 `main`에서 `improve/rN-주제` 브랜치를 만듭니다.
   - 예: `improve/r1-immediate`, `improve/r2-approval-integrity`
2. 작업마다 커밋 하나를 남깁니다. 메시지는 `<type>(<영역>): <요약> (RN-TM)` 형식입니다.
3. 라운드 게이트를 통과하면 사용자에게 병합 여부를 확인받습니다.
4. 병합은 사용자가 기존 PR 흐름으로 진행합니다. 에이전트는 push·병합을 하지 않습니다.

## 라운드 게이트

라운드는 아래를 모두 만족해야 완료입니다.

- [ ] 라운드의 모든 작업이 작업 게이트를 통과 ([04_agent_workflow/verification_gates.md](04_agent_workflow/verification_gates.md))
- [ ] 브랜치 전체에 대해 전체 테스트 통과, 통과 수 ≥ 기준선
- [ ] 라운드 검토 결과 차단 지적 0건
- [ ] 라운드 파일의 "게이트 판정" 절에 결과 기록
- [ ] 사용자 확인이 필요한 수동 점검 항목을 사용자에게 전달
