# 01. 개선 정책

## 목표

"사람이 승인한 댓글만, 설정한 채널에, 민감 정보 유출 없이 게시된다"를 테스트로 증명할 수 있는 상태를 만듭니다.

## 성공 기준

| 목표 | 성공 기준 | 관련 항목 |
| --- | --- | --- |
| 민감 데이터가 배포물에 섞이지 않음 | 배포 zip에 `Cookies`·`Login Data`·`.env`·`chrome-profile-*` 0건 (패키징 스크립트가 검사) | H4 |
| 사람 승인 없이는 게시 불가 | 다른 로컬 프로세스가 생성→승인→게시를 호출하면 거부됨을 테스트로 증명 | H1 |
| 설정한 채널은 끝까지 게시 가능 | 설정에 추가한 채널 영상이 게시 가드를 통과하는 테스트 존재 | H2 |
| API 키가 평문으로 남지 않음 | 기본 실행 후 `.env`에 키 0개, OS 보안 저장소에서 조회 | H3 |
| 불확실한 게시도 사람이 정리 가능 | `OUTCOME_UNKNOWN` 영상을 화면에서 "게시됨/무시"로 해소 가능 | M3 |

공통 기준: 전체 테스트 통과, 통과 수가 기준선보다 줄지 않음.

## 원칙

1. **기존 안전장치는 약화하지 않습니다.**
   예약 상태 머신, 영상당 1회 유일 인덱스, RSS 재확인, fail-closed 동작은 수정 금지 영역입니다.
   바꿔야 한다면 해당 라운드 계획에 사유를 쓰고 사용자 승인을 받습니다.
2. **테스트를 먼저 씁니다.**
   새 테스트는 기준 커밋에서 실패하고 작업 후 통과해야 합니다.
3. **한 작업 = 한 커밋.**
   커밋 메시지에 작업 ID(예: `R1-T2`)를 넣습니다.
4. **라운드마다 브랜치를 따로 씁니다.**
   `main`에서 `improve/rN-주제` 브랜치를 만들고, 라운드 게이트 통과 후 병합 여부를 사용자에게 확인받습니다.
5. **보고는 믿지 않고 다시 실행해 확인합니다.**
   하위 에이전트의 보고는 메인이 명령을 재실행해 검증합니다.
6. **[보고서]·[추정] 항목은 착수 전에 재확인합니다.**
   현재 코드가 보고서와 다르면 계획을 고치고 결정 기록에 남깁니다.

## 범위 밖

- YouTube에 실제 댓글을 게시하는 점검은 사용자가 직접 합니다. 에이전트는 실게시를 하지 않습니다.
- 계정 비밀번호 변경, 세션 재발급 등 계정 조치는 사용자가 직접 합니다.
