# 07. 중단·재개 프로토콜

토큰 소진, 세션 종료, PC 연결 끊김으로 작업이 언제든 멈출 수 있다고 가정합니다.
**진행 상태는 대화가 아니라 이 저장소의 파일과 git 커밋에만 둡니다.** 새 세션은 대화 이력 없이 파일만 읽고 이어갈 수 있어야 합니다.

## 1. 원칙

1. **상태 파일이 진실입니다.** 현재 위치와 다음 행동은 [08_current_state.md](08_current_state.md)에 있습니다. 대화에서 정한 것은 이 파일이나 결정 기록에 적기 전까지 정해진 것이 아닙니다.
2. **단계마다 체크포인트를 남깁니다.** 아래 3절의 시점마다 상태 파일을 갱신하고 커밋합니다.
3. **커밋이 저장 지점입니다.** 커밋되지 않은 변경은 중단 시 "출처 불명의 반쯤 된 작업"이 됩니다. 작업 단위를 작게 유지해 커밋 사이 간격을 짧게 합니다.
4. **모든 단계는 다시 실행해도 안전해야 합니다.** 같은 단계를 두 번 실행해도 결과가 같도록 씁니다(예: 브랜치가 이미 있으면 만들지 않고 전환).
5. **하위 에이전트 보고는 파일로 남깁니다.** 보고는 [logs/](logs/)에 저장한 뒤 판정합니다. 메인 세션이 끊겨도 보고가 사라지지 않습니다.

## 2. 상태 파일 형식

[08_current_state.md](08_current_state.md)는 아래 항목을 항상 최신으로 유지합니다.

| 항목 | 내용 |
| --- | --- |
| 갱신 시각 | KST |
| 브랜치 / HEAD | 현재 브랜치와 마지막 커밋 해시 |
| 현재 라운드 · 단계 | 예: 라운드 1 · 구현 · R1-T3 |
| 작업별 상태 | 라운드 작업 ID별 상태와 마지막 보고 파일 |
| 다음 행동 | 새 세션이 **가장 먼저** 할 일, 한 줄 |
| 진행 중이던 것 | 끊길 때 하고 있던 일과 그 결과가 어디까지 반영됐는지 |
| 미결 질문 | 사용자 답이 필요한 것 |

## 3. 체크포인트 시점

| 시점 | 상태 파일 갱신 | 커밋 |
| --- | --- | --- |
| 라운드 계획 작성 완료 (승인 전) | 예 | 예 (`docs(improve_plan): …`) |
| 사용자 계획 승인 | 예 | 예 |
| 하위 에이전트 실행 **직전** | 예 ("RN-TM 구현 에이전트 실행 중") | 아니오 (작업 트리 깨끗해야 함) |
| 하위 에이전트 보고 수신 | 보고를 `logs/`에 저장 | 아니오 |
| 작업 게이트 판정 | 예 | 예 (상태 파일 + 로그) |
| 라운드 게이트 판정 | 예 | 예 |

## 4. 재개 절차 (새 세션)

1. [08_current_state.md](08_current_state.md)를 읽습니다.
2. 저장소 실제 상태와 대조합니다.
   - `git branch --show-current`, `git log --oneline -5`, `git status --short`
   - 상태 파일의 브랜치·HEAD와 다르면 실제 상태를 기준으로 상태 파일을 고칩니다.
3. 반쯤 된 작업을 처리합니다(5절).
4. 테스트 환경을 확인합니다. 없으면 [04_agent_workflow/roles_and_models.md](04_agent_workflow/roles_and_models.md)의 재생성 명령으로 만듭니다.
5. 상태 파일의 "다음 행동"부터 이어갑니다.

## 5. 반쯤 된 작업 처리

| 발견한 상태 | 판단 | 조치 |
| --- | --- | --- |
| 작업 트리 깨끗, 상태 파일이 "에이전트 실행 중" | 에이전트가 커밋 전에 끊김 | 해당 작업을 처음부터 다시 실행 |
| 작업 트리에 미커밋 변경, 상태 파일이 "에이전트 실행 중" | 에이전트가 작업 도중 끊김 | `git diff`를 `logs/`에 저장한 뒤 변경을 되돌리고 작업 재실행. 부분 결과를 이어 쓰지 않음 |
| 작업 커밋은 있는데 게이트 판정 기록 없음 | 판정 전에 끊김 | 게이트만 다시 실행해 판정 |
| 상태 파일보다 커밋이 앞서 있음 | 상태 갱신 전에 끊김 | 커밋 메시지의 작업 ID로 상태를 맞춘 뒤 게이트 재실행 |
| 원인을 알 수 없는 변경 | 판단 불가 | 건드리지 않고 사용자에게 질문 |

## 6. 새 세션 시작 문장

사용자는 새 세션(같은 프로젝트, 같은 폴더 연결)에서 아래처럼 요청하면 됩니다.

> `improve_plan/07_resume_protocol.md`와 `improve_plan/08_current_state.md`를 읽고 개선 작업을 이어서 진행해줘.

## 7. 토큰 절약 수칙 (중단 확률 줄이기)

- 메인은 큰 파일을 통째로 읽지 않고, 필요한 함수만 `grep`·`sed -n`으로 읽습니다.
- 테스트 출력은 `-q`와 `tail`로 줄입니다.
- 하위 에이전트 보고는 양식([report_format.md](04_agent_workflow/report_format.md))의 항목만 받습니다.
- 라운드가 끝나면 새 세션으로 넘어가는 것을 기본으로 합니다.
