# 라운드 루프

```
계획(메인) ─▶ [사용자 승인] ─▶ 구현(Sonnet) ─▶ 작업 게이트(메인) ─▶ 검토(Sonnet) ─▶ 라운드 게이트(메인) ─▶ [사용자 확인]
                                  ▲                  │ 실패                 │ 차단 지적
                                  └──────────────────┴──────────────────────┘
```

## 1. 계획 (메인)

1. `main` 최신 상태에서 라운드 브랜치를 만듭니다.
2. 라운드 파일의 [보고서]·[추정] 항목을 현재 코드에서 재확인합니다.
3. 작업마다 [작업 계약서](task_contract_template.md)를 작성해 라운드 파일에 넣습니다.
4. 테스트 기준선(통과 수, 실패 목록)을 측정해 기록합니다.
5. 사용자에게 계획 요약과 결정 필요 사항을 보내고 **승인을 받습니다.**

## 2. 구현 (Sonnet, 작업 단위)

1. 메인이 계약서 전문을 프롬프트로 넘겨 구현 에이전트를 실행합니다.
2. 구현 에이전트는 실패 테스트 작성 → 실패 확인 → 수정 → 통과 확인 → 커밋 순서로 작업합니다.
3. [보고 양식](report_format.md)대로 보고합니다.

## 3. 작업 게이트 (메인)

- [verification_gates.md](verification_gates.md)의 G1~G6을 실행합니다.
- 실패하면 실패한 게이트와 출력을 붙여 구현 에이전트를 다시 실행합니다(재시도 규칙은 [escalation_and_metrics.md](escalation_and_metrics.md)).

## 4. 검토 (Sonnet, 라운드 단위)

1. 라운드의 모든 작업이 작업 게이트를 통과한 뒤 한 번 실행합니다.
2. 입력은 **라운드 브랜치의 diff(`main...HEAD`)와 계약서들**뿐입니다.
3. [체크리스트](review_checklist.md)로 검토하고 지적을 차단/권고로 분류합니다.
4. 차단 지적은 해당 작업의 구현 에이전트에 수정 지시로 넘기고, 수정 후 작업 게이트와 검토를 다시 거칩니다.

## 5. 라운드 게이트 (메인)

- [03_roadmap.md](../03_roadmap.md)의 라운드 게이트를 판정합니다.
- 라운드 파일에 결과, 측정값(재작업 횟수 등), 남은 권고 사항을 기록합니다.
- 사용자에게 결과와 수동 점검 항목을 보내고 병합 여부를 확인받습니다.

## 체크포인트

각 단계 사이의 상태 갱신·커밋 시점은 [07_resume_protocol.md](../07_resume_protocol.md) 3절을 따릅니다.
