# 검증 게이트

성공과 실패를 판정하는 기준입니다. G0~G6은 기계적 확인이며 1라운드에서 만드는 `scripts/round_gate.py`가 실행합니다. G7은 모델 판단입니다.

## 작업 게이트 (작업마다)

| ID | 확인 | 방법 | 실패 조건 |
| --- | --- | --- | --- |
| G0 | 보고 형식 | 보고서 필수 항목 존재 여부 | 항목 누락 |
| G1 | 테스트 선행 | 계약서의 새 테스트를 **작업 전 커밋**에서 실행 → 실패, **작업 후 커밋**에서 실행 → 통과 | 작업 전에도 통과하거나, 작업 후에도 실패 |
| G2 | 회귀 없음 | 전체 테스트 실행 | 실패 1건 이상, 또는 통과 수 < 기준선 |
| G3 | 범위 준수 | `git diff --name-only <전>..<후>` ⊆ 수정 허용 파일 | 허용 밖 파일 변경 |
| G4 | 금지 영역 보존 | 수정 금지 영역의 diff가 비어 있는지(함수 단위 추출 비교 또는 패턴 검사) | 금지 영역 변경 |
| G5 | 커밋 규칙 | 작업 후 커밋 수 = 1, 메시지에 작업 ID 포함, 작업 트리 깨끗함 | 커밋 수 ≠ 1, ID 누락, 미커밋 변경 존재 |
| G6 | 비밀 보호 | diff와 새 파일에 키·쿠키 패턴 없음, `.env`·`chrome-profile-*` 변경 없음 | 패턴 발견 |

## 라운드 게이트 (라운드마다)

| ID | 확인 | 방법 |
| --- | --- | --- |
| G2' | 브랜치 전체 회귀 없음 | 라운드 브랜치 끝에서 전체 테스트 |
| G7 | 의도 부합 | 검토 에이전트 보고에서 차단 지적 0건. 2·3라운드는 메인 diff 정독 결과도 차단 0건 |
| G8 | 기록 | 라운드 파일의 게이트 판정 절 작성 완료 |

## 판정 규칙

- **작업 성공**: G0~G6 모두 통과
- **라운드 성공**: 모든 작업 성공 + G2'·G7·G8 통과
- 게이트 결과는 통과/실패만 있습니다. "대체로 통과"는 실패입니다.
- 게이트 자체가 실행 불가(환경 문제 등)이면 판정 보류로 두고 메인이 원인을 해결합니다. 보류를 통과로 간주하지 않습니다.

## 기준선

- 라운드 계획 단계에서 `main` 기준으로 전체 테스트를 실행해 통과 수와 이미 실패하던 테스트 목록을 기록합니다.
- 이미 실패하던 테스트는 G2에서 제외하되, 그 목록이 늘어나면 실패입니다.
