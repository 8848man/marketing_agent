# 역할과 모델 배정

| 역할 | 모델 | 하는 일 | 하지 않는 일 |
| --- | --- | --- | --- |
| 메인 | Opus 5.5 | 코드 조사, 라운드 계획·작업 계약서 작성, 게이트 실행, 판정, 사용자 보고, 에스컬레이션 시 직접 구현 | 대량 구현(에스컬레이션 제외) |
| 구현 에이전트 | Sonnet 5.5 | 계약서대로 실패 테스트 작성 → 수정 → 커밋, 보고서 작성 | 계약서 밖 파일 수정, 수정 금지 영역 변경, push·병합, 브랜치 생성·전환 |
| 검토 에이전트 | Sonnet 5.5 | diff와 계약서만 보고 체크리스트 검토, 지적 등급 판정 | 코드 수정, 커밋 |
| 사용자 | — | 라운드 계획 승인, 결정 사항 선택, 실게시 점검, 병합 | — |

## 메인이 diff를 직접 정독하는 경우

검토 에이전트 결과와 별개로, 메인이 diff 전체를 읽고 판정합니다.

- 2라운드(보안·승인 무결성) 전체
- 3라운드의 락 범위 변경(M2)
- 수정 금지 영역에 대한 변경이 승인된 작업
- 검토 에이전트가 "확신 없음"으로 표시한 지적

## 실행 규칙

- 하위 에이전트는 **한 번에 하나씩** 실행합니다. 같은 작업 폴더를 고치므로 병렬 실행하지 않습니다.
- 하위 에이전트는 매번 새로 시작합니다(이전 대화 맥락 없음).
- 사용자 PC의 저장소는 원격 셸로 다룹니다. 하위 에이전트 프롬프트에 저장소 경로와 셸 사용법을 명시합니다.
- 비밀 파일(`.env`, `data/dashboard/chrome-profile-*`)은 어떤 에이전트도 열지 않습니다. 존재 여부만 확인합니다.

## 테스트 실행 환경

- 원격 셸은 사용자 PC 안의 Linux 가상 환경입니다. 사용자 Windows의 Python과는 별개입니다.
- 가상환경: `$HOME/venv-ma` (Python 3.11.17). 저장소 밖에 있습니다.
- 명령: `PYTHONDONTWRITEBYTECODE=1 $HOME/venv-ma/bin/python -m pytest -q -p no:cacheprovider`
- 원격 셸 세션이 바뀌어 가상환경이 사라졌으면 `uv python install 3.11 && uv venv -p 3.11 $HOME/venv-ma` 후 의존성을 다시 설치합니다.
- Windows 전용 동작(DPAPI, 경로)은 여기서 검증할 수 없으므로 해당 작업 계약서에 사용자 수동 확인 항목을 넣습니다.
